# Domain Docs

Read the root `GLOSSARY.md` before using domain terms in issue titles, proposals, hypotheses, or tests. Read records in `docs/adr/` that apply to the area being changed. In this single-context repository, the root glossary and ADR directory are shared across the codebase.

Use glossary terms as written. When a needed term is missing, record the vocabulary gap for domain modeling. Surface conflicts with relevant ADRs rather than silently overriding them.

If a referenced glossary or ADR directory is absent, continue with the available project context.
